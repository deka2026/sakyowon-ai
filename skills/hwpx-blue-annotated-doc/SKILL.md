# 파란 글씨 주석 정책문서 (hwpx)

정책·금융 계획서를 고칠 때 가장 위험한 것은 **확정된 사실과 아직 확인되지 않은 가정이 같은 서체로 섞여 있는 것**이다. 읽는 사람은 둘을 구별하지 못한 채 합의하고, 나중에 가정이 틀리면 합의 전체가 무너진다.

이 스킬은 그 둘을 **서체로 갈라놓는다**. 확인이 필요한 곳은 파란 굵은 글씨로 두고, 문서 끝에 일람표로 모아 "누구에게 언제 물어야 하고 답이 없으면 무엇이 무너지는지"를 명시한다.

2026-09-25 해바람물자산재단 설립제안서(v1 → v2.0 32쪽 → 법률 대조 v2.1 36쪽)와 사회연대경제기본법 시행령 의견서(12쪽)로 실증.

## 전체 흐름

```
v1 원본 → ①비판 검토(수치 정합성까지) → ②전면 재조립(파란 표시) → ③원문 대조
        → ④확정/미확정 분리 → ⑤확인 일람표 → ⑥한글 실개통 + PDF 눈 검수
```

### ① 비판 검토 — 수치를 직접 더해 볼 것

읽기만 하면 못 찾는다. **표의 숫자를 실제로 합산**하면 설계의 구멍이 드러난다. 실증 사례에서 찾은 것:

- 7대 재원 합계 1,000억 = 시민기금 목표와 동일 → 나머지 두 그릇(펀드 300억·보증 100억)의 **조달원이 없음**
- 3계정 배분 900+60+40 = 1,000억으로 전액 소진 → 같은 결론 보강
- 연간 실행액 누적 840억 vs 계정 잔액 900억 → 아슬아슬하게 성립
- 설비 규모에서 역산한 자부담(0.4~1.4억)과 문서의 융자 한도(1~3억) 불일치

체크 목록:

| 갈래 | 무엇을 보나 |
|---|---|
| 합계 정합 | 소계·총계가 실제로 맞는가. 같은 값이 다른 표에서 다르게 쓰이지 않는가 |
| 성격이 다른 금액의 병렬 | 조성액·발행액·보증여력·관리자산을 한 표에 나란히 놓으면 독자는 더한다 |
| 역산 검증 | 단가·규모로 역산해 문서의 한도·건수와 맞는가 |
| 항구 비용 | 20년 만기 상품의 이차보전처럼 **매년 나가는 비용**을 연간 집행액만 적고 누적을 숨기지 않았나 |
| 법적 근거 공백 | 돈을 빌려주고·받고·보증하는 행위마다 근거 법령이 있는가 |
| 선언과 조문의 괴리 | "시민이 소유한다"면 정관에 **동의권·효력 규정**이 있는가. 추천·의견 청취는 권한이 아니다 |
| 일정의 물리적 가능성 | 인허가 심사 기간을 일정에 넣었는가 |
| 전제의 종속성 | 재원의 몇 %가 제도 개정·타 기관 결정에 묶여 있는가 |

### ② 전면 재조립

수정 건수가 수십 건을 넘고 표 구조까지 바뀌면 REPLIN 교정보다 **재조립이 빠르고 안전하다**(표 행 추가 금지 제약도 피한다).

```bash
python scripts/probe_styles.py "템플릿.hwpx"      # 서식 ID·본문폭·표 서식 채록
```

채록값을 `scripts/hwpx_blue_gen.py` 상단 상수에 옮긴 뒤 build 스크립트를 쓴다.

```python
import sys; sys.path.insert(0, r'...\skills\hwpx-blue-annotated-doc\scripts')
from hwpx_blue_gen import Doc, BODY_W

d = Doc(SRC)                                   # 표지 3문단(secPr 운반) 자동 보존
d.prefix = d.prefix.replace('옛 제목', '새 제목')   # 배너 제목 교체(단일 런이면 그대로 치환)

def cw(*r):                                     # 비율 → 열 폭(합계가 BODY_W와 정확히 일치)
    t = float(sum(r)); w = [int(BODY_W*x/t) for x in r]; w[-1] += BODY_W - sum(w); return w

d.intro('부제 문단')
d.head('1. 장 제목', pb=True)                    # pb=True → 쪽 나눔
d.body('ㅇ 본문. «이 구간이 파란 굵은 글씨»가 된다')
d.table([['머리1','머리2'], ['셀','«셀 안에서도 된다»']], cw(1, 3.6))
d.spacer()
d.save(OUT, '미리보기 텍스트')
```

핵심은 `«...»` 하나다. **본문과 표 셀 어디서든** 이 구간이 파란 굵은 글씨 런으로 분리된다. `save()`가 header.xml에 charPr 사본(원본 서식 + `textColor="#0000CC"` + `<hh:bold/>`)을 만들어 붙이고 itemCnt를 갱신한다.

### ③ 원문 대조 — 법률·고시는 반드시 원문으로

문서가 "○○법 제17조에 따라"라고 적혀 있으면 **그 조문을 직접 읽는다.** 조문 번호가 맞아도 내용이 다를 수 있다. 실증 사례에서:

- 조문 번호(제17조 중개기관, 제18조 전담기관)는 **맞았다**
- 그러나 **지정권자가 지자체가 아니라 장관**이었다
- 걱정하던 업력 요건은 **없었고**, 대신 **대통령령이 정하는 자본금**이라는 새 관문이 있었다
- 가장 큰 것: 제1항은 "투자·융자 등 금융 중개업무"라 하는데 **제2항의 기능 열거에 직접 융자가 없었다**

> **열거 조항은 열거된 것만 읽지 말고 "없는 것"을 찾아라.** 사업의 핵심 행위가 열거에 빠져 있고 대통령령에 위임돼 있으면, 그게 그 사업의 최대 리스크다.

### ④ 확정/미확정 분리

원문 대조 후 문서를 고칠 때 **확인된 것의 파란 표시를 반드시 해제**한다. 그러지 않으면 일람표가 부풀어 진짜 쟁점이 묻힌다. 일람표를 두 표로 나눈다:

- **「확인을 마친 항목」** — 항목 / 확인 결과 (근거 조문 명시)
- **「확인이 필요한 사항」** — 번호 / 사항 / 확인처 / 시기 / **미확인 시 영향**

"미확인 시 영향"이 이 표의 핵심이다. 이것이 없으면 단순한 할 일 목록이고, 있으면 우선순위가 저절로 정해진다.

### ⑤ 의견서로 분기

시행령·고시에 위임된 사항이 모이면 **별도 의견서 문서**를 만든다. 계획서에 섞어 두면 아무도 제출하지 않는다.

의견서 항목은 5칸으로 통일한다: `관련 조항 / 쟁점 / 제안 조문안 / 제안 이유 / 미반영 시 영향`

제안 조문안은 「제○조(제목) ① … ② …」 형태로 **그대로 별지에 옮겨 쓸 수 있게** 쓴다. 2단 표에서 첫 칸을 비우면 항이 이어지는 것처럼 보여 조문 형태가 유지된다.

```python
['제안 조문안', '제○조(중개기관의 사업 범위) ① 법 제17조제2항 각 호의 업무에는 …'],
['',          '1. 중개기관이 관리·운용하는 …'],
['',          '2. 사회연대경제조직에 대한 출자·우선출자 …'],
```

**법리 한계를 지킬 것.** 시행령으로 다른 법률의 적용 범위를 정하면 위임 한계를 넘는다. 그럴 때는 두 갈래로 쓴다 — 시행령에는 확인 절차만, 근본 정리는 법률 개정 병행 건의.

### ⑥ 검수

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File <hwpx-powershell-edit>\scripts\pagecount_auto.ps1 -HwpxPath "out.hwpx" -Pdf
```
PDF를 PyMuPDF로 접촉 시트(6열·42dpi)로 만들어 빈 쪽·넘침을 한눈에 보고, 파란 글씨가 실제로 파랗게 찍혔는지 한 쪽을 100dpi로 렌더해 확인한다.

구조 감사(셀당 문단 1.0, 표 id 유일, 미정의 charPr 0, `treatAsChar="1"` 0, 짝 안 맞는 `«»` 0)를 함께 돌린다.

## 함정

1. **템플릿에 이미 파란 charPr이 있으면 id가 겹친다.** 산출물을 다시 템플릿으로 쓰지 말고 **항상 원본에서 출발**할 것. 실증 사례에서 v2.1은 v2.0이 아니라 v1 원본을 템플릿으로 썼다.
2. **표지 배너 표는 본문폭과 같아 "초과"로 보인다**(48190 vs horzsize 48188). 원본 설계이므로 건드리지 말 것. 새로 만드는 표만 본문폭 이하로.
3. `probe_styles.py`의 "첫 표"는 배너 표다. 본문 서식은 상위 문단 인덱스 3 이후의 표에서 채록한다(스크립트가 이미 건너뛴다).
4. **`«»` 짝이 안 맞으면 조용히 깨진다.** 추출 텍스트에서 `«`와 `»` 개수를 세어 둘 다 0인지 확인한다(런 분리 후에는 마커가 사라지는 것이 정상).
5. 본문에 `<` `>` 금지, `&`는 자동 이스케이프. 「」·①·ⓐ·≤·— 는 그대로 쓸 수 있다.
6. **정정한 옛 표현을 본문에서 인용할 때** 검증 grep이 "잔존"으로 잡는다. `v1의 "마을당 1~3억"은 …으로 정정했다` 같은 의도적 인용은 카운트 1을 예상값으로 둔다.
7. 열 폭 합계가 BODY_W와 1이라도 다르면 assert로 막힌다 — `cw()`가 마지막 열에 잔차를 몰아 준다.

## 파일

| 경로 | 내용 |
|---|---|
| `scripts/probe_styles.py` | 템플릿의 서식 ID·본문폭·표 서식 채록 |
| `scripts/hwpx_blue_gen.py` | Doc 클래스 — 문단·표 생성, `«»` 파란 런 분리, header charPr 패치, OCF 재패키징 |
