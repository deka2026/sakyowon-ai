# 정관 사업영역을 사업자등록 업종으로 옮기기

2026-10-20 망남마을협동조합 설립서류(정관 별표 1의 KSIC 20개 → 업종코드 19개)로 확립·검증.

## 먼저 알아야 할 것 — 두 분류는 다르다

| | 한국표준산업분류(KSIC) | 국세청 업종코드 |
|---|---|---|
| 자릿수 | 5 | 6 |
| 만든 곳·목적 | 통계청 · 통계 작성 | 국세청 · 조세행정(경비율 등) |
| 적는 곳 | 협동조합 **설립신고서**, 정관 별표 | **사업자등록 신청서**의 업태·종목 |
| 예 | 56111 한식 일반 음식점업 | 552101 한식 일반 음식점업 |

번호가 전혀 다르다. 정관에 KSIC를 적어 두었다고 그 번호를 신청서에 옮기면 틀린다.

## 절차

### 1. 정관에서 사업 목록을 꺼낸다

사업의 종류 조항(보통 제59조 같은 사업 조문)과 별표의 KSIC 목록을 본다. 정관에 KSIC가 없으면 먼저 그것부터 정한다.

### 2. KSIC → 업종코드를 조회한다

```bash
python scripts/lookup_bizcode.py 56111 47122 35114
python scripts/lookup_bizcode.py --file ksic.txt --pause 2
```

출처는 `upjong.co.kr` 의 KSIC 11차 ↔ 업종코드 연계표다. 통계분류포털(kssc.kostat.go.kr)은 브라우저 접근이 막히는 일이 잦다.

스크립트가 429로 막히면 Claude 의 브라우저 도구로 같은 URL 을 열어도 된다. 한 번에 여러 개를 WebFetch 로 던지면 거의 반드시 429가 난다.

```
https://upjong.co.kr/korean-standard-industry-classification/ksic-<5자리>/
```

### 3. 주업종을 고른다

**매출이 가장 클 사업**이 주업종이다. 사업자등록의 주업종은 사업자등록증에 처음 찍히고 업종별 경비율의 기준이 된다.

- 사업계획서가 있으면 그 매출 전망으로 정한다
- 설립 첫해에 수익이 0인 사업(허가만 받는 발전사업 같은 것)은 조합의 정체성이어도 주업종이 될 수 없다

### 4. 등록 시기를 둘로 나눈다

| | 내용 |
|---|---|
| 설립과 동시에 등록 | 그 해에 실제로 여는 사업만 |
| 사업을 시작할 때 추가 | 시설·인허가가 필요한 사업. 사업자등록 정정신고로 더한다(부가가치세법 시행령 제14조) |

업종을 많이 등록한다고 세금이 늘지는 않지만, 하지 않는 업종이 있으면 부가가치세 신고 때 업종별 매출 구분이 번거로워진다. **시작하는 것만 등록**을 권한다.

### 5. 법인 명의로 등록할 수 없는 업종을 걸러낸다

정관에 있어도 사업자등록이 안 되는 것이 있다. 2026-10-20 사례:

> **농어촌민박(KSIC 55104 / 업종코드 551005)** — 「농어촌정비법」상 그 마을에 사는 개인만 신고할 수 있어 **조합 명의로는 등록되지 않는다.** 조합은 예약·홍보·품질관리를 맡는 630601(기타 여행 보조 및 예약 서비스업)로 등록하고, 민박 신고는 조합원 각자가 한다.

이런 항목은 빼되 **왜 뺐는지를 문서에 남긴다.** 나중에 "정관에 있는데 왜 등록 안 했나"는 질문이 반드시 나온다.

### 6. 첨부서류가 늘어나는 업종을 확인한다

- **재생용 재료 수집 및 판매업(514971)** · 금지금·연료 도소매업 · 과세유흥장소 → **자금출처명세서**를 함께 내야 한다
- 인허가 업종은 허가증·신고확인증 사본

실제로 시작할 때 추가하는 편이 신청이 간단하다.

### 7. 업종이 많으면 별지를 만든다

사업자등록 신청서의 업태·종목 칸은 두 줄뿐이다. 그 이상이면 「사업의 종류 명세서」를 만들어 함께 낸다. 각 행에 **업종코드 · KSIC · 정관 조문(호·목)** 을 나란히 적으면 설립신고서와 대조하기 좋다.

## 함정

1. **한 KSIC 에 업종코드가 여럿 붙는다.** 47215(채소·과실 소매)는 522040(채소·뿌리작물)과 522050(과일·견과류), 91139(기타 스포츠시설)는 다섯 개(정구장·눈썰매장·야구연습장 …), 76390은 세 개다. 적용범위 설명을 읽고 골라야 한다 — 스크립트는 여러 개가 나오면 알려 준다.
2. **업종코드는 귀속연도마다 바뀐다.** 조회값은 조회 시점의 귀속연도 기준이다. 문서에 기준 연도를 적고, 신청 직전 홈택스 「기준·단순 경비율(업종코드) 조회」로 재확인하라고 써 둔다.
3. **KSIC 자체도 차수가 있다.** 현행은 제11차(통계청 고시 제2024-2호, 2024. 7. 1. 시행). 정관 별표가 10차 기준이면 먼저 맞춘다.
4. **조합법인 칸을 혼동하지 말 것.** 협동조합기본법에 따른 일반협동조합은 「조세특례제한법」 제72조의 조합법인이 **아니다**(농협·수협·신협 등 개별법 조합만 해당). 신청서에서 '미해당'이다.

## 이미 만들어진 설립서류 세트를 고칠 때

서류 묶음이 **그룹웨어나 서버의 생성기로 만들어진 것**이면 그쪽이 정본이다. 로컬 파일을 고쳐도 다시 내려받으면 원래대로 돌아간다.

- 로컬 수정과 **함께 생성기에도 반영**해야 한다. 안 하면 다음 내려받기에서 되돌아간다
- 묶음에 안내문이 있으면 **기관별 제출 서류 목록**에도 새 서류를 더한다

로컬 hwpx 를 고치는 요령은 `hwpx-powershell-edit` 을 따르되,

- 표 **행 추가는 하지 말 것**. 칸이 모자라면 별지 문서를 따로 만든다
- 셀 **텍스트 교체**는 `apply_by_index.ps1` 의 SET 으로 안전하게 된다
- 새 문서를 만들 때 묶음과 서식을 맞추려면 기존 문서를 템플릿으로 삼고, **표 첫 행·첫 열의 paraPr 을 가운데로 바꾸는 후처리**를 직접 넣어야 한다. `hwpx_house_rules.apply_rules` 는 그것까지 해 주지 않는다
- 묶음이 쓰는 md 문법(`-> ` 가운데 정렬, `* ` 부가 설명)을 `md-to-hwpx-docset` 의 gen.py 는 모른다. 그 문법이 필요하면 전용 조립 스크립트를 쓴다

## 함께 쓰는 스킬

- `hwpx-powershell-edit` — 기존 hwpx 최소 편집, 서식 채록
- `md-to-hwpx-docset` — md 원본으로 한글 문서 묶음 만들기
