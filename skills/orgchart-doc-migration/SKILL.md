# 조직개편 → 문서 묶음 갱신

조직개편이 나면 이미 써둔 사업계획서 대여섯 건의 "담당 팀" 표기가 한꺼번에 낡는다.
이 스킬은 세 단계로 그걸 처리한다 — **조직도 채록 → 대응표 확정 → 문서 묶음 일괄 치환**.

실증: 2026-09-10~11 전남광주통합특별시 통합조직도 v12(시민주권본부 5과 20팀 → 4과 12팀 +
기본사회담당관 3팀) 반영. 발제문 1건 신규 생성(16쪽·표 23개) + 참고문서 4종 점검·2종 치환
(22건, 잔존 0).

---

## 1단계 — 조직도 채록

행정 조직도 PDF는 과·팀 이름이 **세로쓰기**다. 텍스트를 그냥 뽑으면 글자가 흩어진다.

```bash
# 먼저 Read 도구로 PDF를 이미지로 보고 대상 영역의 픽셀 위치를 눈으로 잡는다
# pt = px / 이미지폭 * 페이지폭(보통 1190pt 가로)
PYTHONIOENCODING=utf-8 python scripts/orgchart_columns.py 조직도.pdf 0 540 850 370 700
```

출력이 `자|치|분|권|과|31|행정|조직관리|...` 형태로 나온다 — 과 이름 + 정원 + 팀 이름 순.

**함정**
- 콘솔 인코딩이 cp949면 전부 `��`로 보인다. 실제로는 잘 읽힌 것이니 `PYTHONIOENCODING=utf-8`만 붙이면 된다.
- 부시장/청사 구분 라벨(`무 안`, `동 부`)은 도형으로 그려져 텍스트에 안 잡힐 수 있다. 잡히지 않으면 추측하지 말고 "확인 필요"로 남긴다.
- 정원 숫자는 과 이름 바로 아래 한 줄에 온다. 과별 정원 합으로 본부 규모를 검산한다.

## 2단계 — 대응표 확정 (사람이 판단하는 자리)

기계가 할 수 없는 부분이다. 구 팀 하나하나에 대해 **어느 신 팀이 그 업무를 받는가**를 정한다.
표로 만들어 문서에 싣는다 — 이 표가 3단계 치환 규칙이자 산출 문서의 뼈대가 된다.

판단할 때 꼭 확인할 것:

| 확인 | 왜 |
|---|---|
| **대응 팀이 없는 구 팀** | 기능이 본부 밖으로 나갔는지, 아예 사라졌는지. 이게 개편안의 최대 쟁점이다 |
| **두 구 팀이 한 신 팀으로 합쳐지는 곳** | 문장에서 "A 주관, B 협업"이 "A 주관, A 협업"이 되어버린다 |
| **마커(❶❷❺ 등)의 의미 변화** | 소속이 바뀐 팀 앞의 옛 마커는 함께 지워야 한다 |
| **다른 국·과와의 중복** | 새 조직도에서 같은 업무를 가진 부서가 생겼는지 |

## 3단계 — 문서 묶음 일괄 치환

`rules.txt`(UTF-8, `옛말<TAB>새말`)를 쓰고 문서마다 돌린다.

```bash
PYTHONIOENCODING=utf-8 python scripts/hwpx_retag.py rules.txt 원본.hwpx 출력_팀명갱신_v1.0.hwpx
```

- **긴 것·문구 단위를 위에** 적는다. 앞 규칙이 가져간 구간은 뒤 규칙이 건드리지 않는다.
  - `❺ 에너지기본사회팀` → `태양광산업과(햇빛소득마을)` (마커까지 제거)
  - 그 아래 `에너지기본사회팀` → `태양광산업과(햇빛소득마을)` (마커 없는 자리)
- 2단계에서 찾은 "합쳐져서 중복되는 문장"은 **문구 단위 규칙**으로 맨 위에 둔다.
  - `공동체기업육성팀 주관, 시민자산금융팀 · 시민자산AI팀 협업` → `사회연대경제육성팀 주관, 사회연대경제지원팀 협업`
- 바뀐 글자만 빨간색이 된다. 사람이 한글에서 보고 수락한 뒤 검정으로 정리한다.
- 끝나면 스크립트가 **잔존 옛말 0건**을 확인해 준다. 양방향 검증(있어야 할 것/없어야 할 것)이다.

### 왜 hwpx-powershell-edit 의 apply_by_index 를 안 쓰는가

`apply_by_index.ps1`의 REPLIN은 조각이 한 인덱스 안에서 **정확히 1회** 나와야 하고,
**여러 `<hp:t>` 런에 걸쳐 잘린 낱말은 찾지 못한다**. 조직개편 치환은 같은 낱말이 문서
전체에 수십 번 나오고, 표 셀에서 `❹ 공동체기업` + `육성팀` 처럼 자주 잘린다.
`hwpx_retag.py`는 모든 런을 이어붙인 문자열에서 찾은 뒤 런 경계를 넘는 것도 처리한다.
단건·문단 교체는 여전히 `hwpx-powershell-edit` 쪽이 낫다.

## 4단계 — 12pt 규칙 적용

사교원 문서는 본문·표 셀 모두 12pt다. 옛 문서는 10pt인 경우가 많다.

```bash
PYTHONIOENCODING=utf-8 python scripts/hwpx_bump_pt.py 출력1.hwpx 출력2.hwpx
```

height 1200 미만인 charPr을 전부 1200으로 올린다. **빨간 사본도 같은 규칙으로 함께 올라간다**
(사본 역시 charPr이므로) — 이걸 빠뜨리면 교정 부분만 10pt로 남는다.
글자를 키우면 표 줄이 접혀 쪽수가 늘어나므로 **쪽수 재측정과 열 폭 손질을 함께** 한다.

## 마무리 — 쪽수 확인

`hwpx-powershell-edit/scripts/hwpx_pagecount.ps1 -Pdf` 로 재측정하고 PDF를 눈으로 본다.

**한글이 이미 떠 있으면 하지 말 것.** COM의 `$hwp.Quit()`이 사용자가 열어둔
미저장 문서까지 닫는다(→ `feedback-never-kill-hangul`). 먼저 확인한다:

```powershell
Get-Process | Where-Object { $_.ProcessName -match 'Hwp' }
```

떠 있으면 치환·생성까지만 하고 "쪽수 미확인"을 정확히 보고한다. 지어내지 않는다.

## 산출 문서를 함께 만들 때

구·신 대응표는 그 자체로 발제문·검토안의 뼈대가 된다. 문서를 새로 조립할 때는
`hwpx-powershell-edit` 경로 D(`hwpx_gen.py` + `docutil.patch_table`)를 쓰고,
본문폭·표 폭·셀 리스트 규칙은 그 스킬의 함정 모음을 따른다.

관련 스킬: `hwpx-powershell-edit`(문서 생성·단건 교정), `sujeonghae-routine`(빨간펜 교정)
